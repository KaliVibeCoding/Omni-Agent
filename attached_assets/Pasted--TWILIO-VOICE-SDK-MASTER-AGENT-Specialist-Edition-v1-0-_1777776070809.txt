## ACCESSTOKENS — THE JWT CONTRACT

AccessTokens are short-lived JSON Web Tokens that authenticate SDK
end-users to Twilio. You mint them server-side and deliver to the
client.

### Token Lifetime
- Default TTL: 1 hour (3600 seconds)
- Maximum TTL: 24 hours
- Recommendation: 1-hour tokens with client-side refresh logic

### Decoded payload (anatomy)

```json
{
  "jti": "SK835c7c8ac38c0617205f41fd71d4bb38-1643132114",
  "iss": "SKxxxxxxxx",
  "sub": "ACxxxxxxxx",
  "iat": 1643132114,
  "exp": 1643135714,
  "grants": {
    "identity": "agent_alice",
    "voice": {
      "incoming": { "allow": true },
      "outgoing": { "application_sid": "APxxxxxxxx" },
      "push_credential_sid": "CRxxxxxxxx"
    }
  }
}
```

**Field by field:**
- `iss` — API Key SID (starts `SK`)
- `sub` — Account SID (starts `AC`)
- `jti` — JWT ID (`<API_KEY_SID>-<timestamp>`)
- `iat` / `exp` — issued-at / expiration epoch seconds
- `grants.identity` — string used inside `<Client>` TwiML to reach this user
- `grants.voice.incoming.allow` — `true` to accept inbound calls
- `grants.voice.outgoing.application_sid` — TwiML App SID for outbound
- `grants.voice.push_credential_sid` — for mobile incoming calls
  (CRxxx for APNs/FCM)

### When AccessToken errors occur
Decode the JWT at jwt.io and check:
1. Is the token expired (`exp` past)?
2. Is `grants.identity` set?
3. Is `application_sid` a valid TwiML App SID?
4. Is `push_credential_sid` correct (mobile)?
5. Is `incoming.allow` set to `true` if you expect inbound?

### Mint Patterns — All 7 Server Languages

#### Node.js (twilio-node v5)

```javascript
import twilio from 'twilio';

export function mintVoiceToken(identity) {
  const AccessToken = twilio.jwt.AccessToken;
  const VoiceGrant = AccessToken.VoiceGrant;

  const token = new AccessToken(
    process.env.TWILIO_ACCOUNT_SID,
    process.env.TWILIO_API_KEY_SID,
    process.env.TWILIO_API_KEY_SECRET,
    { identity, ttl: 3600 }
  );

  token.addGrant(new VoiceGrant({
    outgoingApplicationSid: process.env.TWIML_APP_SID,
    incomingAllow: true,
    pushCredentialSid: process.env.PUSH_CREDENTIAL_SID, // mobile only
  }));

  return token.toJwt();
}
```

## TWIML APPS

A TwiML App is a Twilio resource holding three URLs:

1. **Voice URL** — Twilio POSTs here when an SDK user makes an
   outbound call. You return TwiML that tells Twilio what to do.
2. **Voice Fallback URL** — used if the primary URL fails (4xx/5xx).
3. **Voice Status Callback URL** — receives a POST when the parent
   call leg ends.

### Create a TwiML App via CLI

```bash
twilio api:core:applications:create \
  --friendly-name "RJ Voice SDK App" \
  --voice-url "https://your-app.com/voice/sdk-outbound" \
  --voice-method POST \
  --voice-fallback-url "https://your-app.com/voice/fallback" \
  --voice-fallback-method POST \
  --status-callback "https://your-app.com/voice/sdk-status" \
  --status-callback-method POST
```

The output gives you `APxxxxxxxx` — that's the SID you put in
`outgoingApplicationSid` when minting AccessTokens.

### Voice URL Handler — Outbound from SDK

When `agent_alice` clicks "Call" in your web app and dials a PSTN
number, Twilio POSTs to your Voice URL with these params:

- `From` = `client:agent_alice`
- `To` = whatever you set in `Device.connect({ params: { To: '...' } })`
- `CallSid` = parent leg SID
- All other standard voice webhook params

You return TwiML that `<Dial>`s the destination:

```javascript
// Example handler — Express + twilio-node
import twilio from 'twilio';
import express from 'express';

const app = express();
app.use(express.urlencoded({ extended: false }));

const validate = twilio.webhook({
  validate: true,
  authToken: process.env.TWILIO_AUTH_TOKEN,
});

app.post('/voice/sdk-outbound', validate, (req, res) => {
  const r = new twilio.twiml.VoiceResponse();
  const dial = r.dial({
    callerId: process.env.TWILIO_OUTBOUND_CALLER_ID, // your Twilio number
    answerOnBridge: true,
  });

  const to = req.body.To;
  if (/^\+\d+$/.test(to)) {
    dial.number({
      statusCallback: 'https://your-app.com/voice/leg-events',
      statusCallbackEvent: 'initiated ringing answered completed',
      statusCallbackMethod: 'POST',
    }, to);
  } else if (to?.startsWith('client:')) {
    dial.client(to.replace('client:', ''));
  } else if (to?.startsWith('sip:')) {
    dial.sip(to);
  } else {
    r.say('Invalid destination.');
    r.hangup();
  }

  res.type('text/xml').send(r.toString());
});
```

**Server-side validation:** Always validate `To` against an allowlist
before dialing — distributed clients can send arbitrary `To` values
and run up your bill on premium-rate numbers.

### Inbound TwiML — PSTN to SDK User

For inbound calls, configure your Phone Number's Voice Webhook
(NOT the TwiML App — phone numbers point at their own URL) to
return TwiML that uses `<Dial><Client>`:

```xml
<Response>
  <Dial answerOnBridge="true">
    <Client>
      <Identity>agent_alice</Identity>
      <Parameter name="caseId" value="RJ2026-001" />
    </Client>
  </Dial>
</Response>
```

The custom `<Parameter>` elements arrive in the SDK as call
parameters — useful for passing context.

## CALL LEGS — Parent & Child (CRITICAL CONCEPT)

Every SDK-involved call creates **two Call Resources** in your
account: a parent leg and a child leg.

### Inbound (PSTN → SDK)

```
Caller +15555552222 ── PSTN ──> Twilio Number +15555558888
                                     │
                                     │  (parent Call: CA_PARENT)
                                     │  Direction: Incoming
                                     │  From: +15555552222
                                     │  To:   +15555558888
                                     │  Type: Phone
                                     ▼
                              <Dial><Client>SalesAgent1</Client></Dial>
                                     │
                                     │  (child Call: CA_CHILD)
                                     │  Direction: Outgoing Dial
                                     │  From: +15555552222
                                     │  To:   client:SalesAgent1
                                     │  Type: Client
                                     ▼
                                SDK end-user
```

**SDK Call SID (inbound) = CHILD Call SID.**

### Outbound (SDK → PSTN)

```
SDK end-user (SalesAgent1)
        │
        │  (parent Call: CA_PARENT)
        │  Direction: Incoming    ← incoming TO Twilio FROM the SDK
        │  From: client:SalesAgent1
        │  To:   (empty — TwiML not yet retrieved)
        │  Type: Client
        ▼
   Twilio fetches TwiML App Voice URL
        │
        ▼
   <Dial callerId="+15555558888"><Number>+15552229999</Number></Dial>
        │
        │  (child Call: CA_CHILD)
        │  Direction: Outgoing Dial
        │  From: +15555558888
        │  To:   +15552229999
        │  Type: Client
        ▼
   PSTN destination
```

**SDK Call SID (outbound) = PARENT Call SID.**

### Status Callback Header Reference

When you receive a status callback, check these properties:

| Field | Meaning |
| ----- | ------- |
| `CallSid` | The leg this callback is about |
| `ParentCallSid` | Set ONLY on child legs, after parent has spawned the child |

**If `ParentCallSid` is missing**, the callback is for the parent leg
itself (or the child hasn't been created yet). Don't assume the
absence means anything else.

For recording linkage, conference linkage, and analytics, always
preserve both SIDs in your DB — they're how you reconstruct the full
call tree later.

## VOICE JAVASCRIPT SDK — BROWSER & ELECTRON

**Install:** `pnpm add @twilio/voice-sdk`

### Setup & Outbound Call

```javascript
import { Device } from '@twilio/voice-sdk';

// 1. Fetch token from your server
const res = await fetch('/api/voice/token');
const { token } = await res.json();

// 2. Create Device
const device = new Device(token, {
  logLevel: 1,
  codecPreferences: ['opus', 'pcmu'], // opus = better quality
  // edge: 'sydney',  // optional regional ingress
});

// 3. Register for incoming calls
await device.register();

// 4. Listen for incoming
device.on('incoming', (call) => {
  // Show UI: who's calling, accept/reject buttons
  console.log('Incoming from', call.parameters.From);
  console.log('Custom params:', call.customParameters);

  // Accept
  call.accept();

  // Or reject
  // call.reject();
});

// 5. Make outbound call
const call = await device.connect({
  params: {
    To: '+15551234567',         // arrives in your Voice URL as `To` param
    customField: 'caseId-RJ001' // arrives as POST param too
  }
});

// 6. Call lifecycle
call.on('accept', () => console.log('Connected'));
call.on('disconnect', () => console.log('Hung up'));
call.on('cancel', () => console.log('Caller canceled before answer'));
call.on('reject', () => console.log('Rejected by remote'));
call.on('error', (err) => console.error('Call error', err));

// 7. Mid-call controls
call.mute(true);            // mute mic
call.sendDigits('1234#');    // send DTMF
call.disconnect();           // hang up

// 8. Token refresh (before expiry)
device.updateToken(newJwt);

// 9. Cleanup
device.destroy();
```

### Setup with PushKit (mandatory for incoming calls)

```swift
import TwilioVoice
import PushKit
import CallKit

class VoiceManager: NSObject, PKPushRegistryDelegate, NotificationDelegate, CallDelegate {
    let pushRegistry = PKPushRegistry(queue: .main)
    var accessToken: String = ""
    var activeCall: Call?
    var callKitProvider: CXProvider?

    override init() {
        super.init()
        // Register for VoIP push notifications
        pushRegistry.delegate = self
        pushRegistry.desiredPushTypes = [.voIP]
    }

    // 1. Push registration
    func pushRegistry(_ registry: PKPushRegistry,
                      didUpdate credentials: PKPushCredentials,
                      for type: PKPushType) {
        let deviceToken = credentials.token
        // Register with Twilio
        TwilioVoiceSDK.register(
            accessToken: accessToken,
            deviceToken: deviceToken
        ) { error in
            if let error = error {
                print("Push registration failed: \(error)")
            }
        }
    }

    // 2. Incoming push → CallInvite
    func pushRegistry(_ registry: PKPushRegistry,
                      didReceiveIncomingPushWith payload: PKPushPayload,
                      for type: PKPushType,
                      completion: @escaping () -> Void) {
        TwilioVoiceSDK.handleNotification(
            payload.dictionaryPayload,
            delegate: self,
            delegateQueue: nil
        )
        completion()
    }

    // 3. CallInvite delegate
    func callInviteReceived(callInvite: CallInvite) {
        // Report to CallKit, present native UI
        let update = CXCallUpdate()
        update.remoteHandle = CXHandle(type: .generic, value: callInvite.from ?? "Unknown")
        callKitProvider?.reportNewIncomingCall(with: callInvite.uuid,
                                               update: update,
                                               completion: { _ in })
        // Save invite to accept later in CallKit answer action
    }

    // 4. Make outbound call
    func makeCall(to: String) {
        let connectOptions = ConnectOptions(accessToken: accessToken) { builder in
            builder.params = ["To": to]
        }
        activeCall = TwilioVoiceSDK.connect(options: connectOptions, delegate: self)
    }

    // 5. CallDelegate methods
    func callDidConnect(call: Call) { print("Connected") }
    func callDidDisconnect(call: Call, error: Error?) { print("Hung up") }
    func callDidFailToConnect(call: Call, error: Error) { print("Failed: \(error)") }
}
```

**Push Credential setup:** Generate VoIP Services certificate from
Apple Developer → upload to Twilio Console (Voice → Manage → Push
Credentials) → get `CRxxxxxxxx` SID → put in
`grants.voice.push_credential_sid` of AccessToken.

## SECURITY HARDENING (Voice SDK Specific)

✅ Mint AccessTokens server-side ONLY. Never embed API Key Secret
   in clients.
✅ Tokens scoped per user — `identity` is unique per end-user
   (e.g., user ID, never a shared "default").
✅ Validate `To` parameter server-side in your Voice URL handler
   against an allowlist before dialing.
✅ Lock Dialing Permissions to allowlist countries on the account.
✅ Set short token TTLs (1h) and refresh client-side before expiry.
✅ Push Credentials rotated on cert expiry (APNs certs expire yearly).
✅ Validate `X-Twilio-Signature` on every voice webhook.
✅ Use `answerOnBridge="true"` on `<Dial>` for accurate billing
   (call only marked in-progress when bridged, not when ringing).
✅ HTTPS only — no token delivery over HTTP.
✅ For browser apps, treat the token endpoint behind your normal
   session auth — only authenticated users get a token.

❌ NEVER share an AccessToken across multiple end-users
❌ NEVER expose your TwiML App SID in source code that gets bundled
   to the client (it's not secret per se, but treat as sensitive)
❌ NEVER rely on client-side validation alone — always re-validate
   destinations server-side

## DEBUG WORKFLOW (When Things Break)

When an SDK call fails, work through this checklist:

### 1. Decode the AccessToken at jwt.io
- Is `exp` in the future?
- Is `grants.identity` set?
- Is `grants.voice.outgoing.application_sid` a valid TwiML App SID?
- Is `grants.voice.incoming.allow` set if you expected inbound?
- Is `grants.voice.push_credential_sid` set for mobile inbound?

### 2. Check Twilio Debugger Console
URL: console.twilio.com/monitor/logs/debugger
Look for warnings about: webhook failures, TwiML parse errors,
token validation errors, push delivery failures.

### 3. Check Call Logs
URL: console.twilio.com/monitor/logs/calls
- Was the parent Call created? What status?
- Is there a child Call? What status?
- Did Twilio successfully fetch your Voice URL?

### 4. SDK-side error events
- JavaScript: `device.on('error', err => ...)` and `call.on('error', ...)`
- iOS: `CallDelegate.callDidFailToConnect(call:error:)`
- Android: `Call.Listener.onConnectFailure(call, callException)`
- React Native: `call.on(Call.Event.ConnectFailure, error => ...)`

### 5. Common errors
- `31201` — Generic error, check Debugger
- `31202` — Authentication failed (bad token)
- `31203` — Invalid AccessToken header
- `31204` — Invalid AccessToken issuer/subject
- `31205` — Token expired
- `31206` — Rate exceeded
- `31207` — JWT signature failed verification
- `31208` — Permissions denied (incoming.allow=false on inbound)

Full list: twilio.com/docs/api/errors
