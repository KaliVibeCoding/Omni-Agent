## MESSAGING CHANNELS — COMPLETE MAP

### SMS (Short Message Service)

- **Long codes:** Standard 10-digit phone numbers
- **Short codes:** 5-6 digit dedicated numbers (US/CA/UK)
- **Alphanumeric senders:** Where regionally permitted (UK, EU)
- **Encoding:** GSM-7 (160 chars) auto-falls-back to UCS-2 (70 chars)
  when emoji/special chars present (Smart Encoding feature handles)
- **Segmentation:** Messages >160 GSM-7 / >70 UCS-2 split into
  segments; concatenated reassembly on the device

### MMS (Multimedia Messaging Service)

- **Media size:** ≤ 5 MB total per message (US/CA), varies by carrier
- **Supported types:** image/jpeg, image/png, image/gif, image/bmp,
  audio/mp3, audio/wav, audio/3gpp, audio/aac, audio/mp4, video/mp4,
  video/3gpp, application/pdf, text/vcard, text/x-vcard
- **Up to 10 media URLs per message** (`MediaUrl` accepts repeated)
- **Inbound MMS storage:** Media stored in Twilio's Media Content
  Service (default 7-day retention, configurable)

### WhatsApp Business

- **Sender:** WhatsApp-enabled Twilio number (sandbox or approved)
- **Templates required** for business-initiated messages
- **24-hour customer-care session window:** After user msgs you,
  free-form replies allowed for 24h; outside that, must use template
- **Template categories:** Marketing, Utility, Authentication
- **Template approval** via Meta Business Manager (typically minutes
  to hours, longer for Marketing)

### RCS Business Messaging (GA since 2025)

- **Branded sender** with logo, verified badge, brand color
- **Rich content:** cards, carousels, suggested replies, suggested
  actions (call/URL/location/calendar)
- **Read receipts + typing indicators**
- **Automatic SMS fallback** when device doesn't support RCS
- **Sender registration via RBM** (1-3 weeks approval)
- **Routed via Messaging Service** with channel sender added

## MESSAGES RESOURCE — THE CORE API

### Endpoint

```
POST https://api.twilio.com/2010-04-01/Accounts/{AccountSid}/Messages.json
```

### Required Parameters (one of each group)

**Recipient (one of):**
- `To` (always required) — E.164 (`+1...`), `whatsapp:+1...`,
  `messaging:+1...` (RCS), or `client:identity` (Conversations)

**Sender (exactly ONE of):**
- `From` — Twilio number, alpha sender, short code
- `MessagingServiceSid` — `MGxxxx` (recommended for production)
- (For WhatsApp) `From: whatsapp:+1...`
- (For RCS) Use `MessagingServiceSid` with RCS sender configured

**Content (one of):**
- `Body` — text up to 1600 chars (will segment if >160 GSM-7)
- `MediaUrl` — public URL to media (repeatable, ≤10)
- `ContentSid` — `HXxxxx` Content Template SID (preferred for
  cross-channel rich content)

### Common Optional Parameters

| Param | Purpose |
| ----- | ------- |
| `StatusCallback` | Webhook URL for delivery updates |
| `ApplicationSid` | TwiML App for status callback routing |
| `MaxPrice` | Cap per-segment cost (e.g., `0.05`) |
| `ProvideFeedback` | `true` for delivery receipts where supported |
| `ValidityPeriod` | Seconds before send-attempt expires (1–14400) |
| `SmartEncoded` | `true` — auto-replace fancy unicode with GSM-7 lookalikes |
| `ScheduleType` | `fixed` for scheduled (requires Messaging Service) |
| `SendAt` | ISO 8601 future timestamp (≤7 days out) |
| `SendAsMms` | `true` to force MMS even with no media |
| `ContentVariables` | JSON map for Content Template var substitution |
| `RiskCheck` | `enable` / `disable` (sender risk evaluation) |
| `ShortenUrls` | `true` (Messaging Service must have link shortening) |

### Example — Plain SMS (Node.js)

```javascript
import twilio from 'twilio';

const client = twilio(
  process.env.TWILIO_API_KEY_SID,
  process.env.TWILIO_API_KEY_SECRET,
  { accountSid: process.env.TWILIO_ACCOUNT_SID }
);

const msg = await client.messages.create({
  to: '+15551234567',
  messagingServiceSid: process.env.TWILIO_MS_SID,
  body: 'Your code is 482-913. Valid 5 minutes. Reply STOP to opt out.',
  statusCallback: 'https://your-app.com/sms/status',
});

console.log('Message SID:', msg.sid);
```

## MESSAGE STATUS LIFECYCLE

| Status | Meaning |
| ------ | ------- |
| `accepted` | Twilio queued for processing |
| `scheduled` | Future-dated send queued |
| `queued` | In delivery queue |
| `sending` | Handing to carrier |
| `sent` | Carrier accepted |
| `delivered` | Confirmed delivered to handset (where supported) |
| `undelivered` | Delivery failed (carrier rejected / handset off / blocked) |
| `failed` | Twilio could not send (config/auth issue) |
| `read` | WhatsApp/RCS only — recipient opened |
| `received` | Inbound message — for context, not for outbound tracking |
| `canceled` | Scheduled message canceled before send |

### Status Callback Webhook

When you set `statusCallback`, Twilio POSTs at each status transition:

```
MessageSid=SM...
MessageStatus=delivered
To=+15551234567
From=+15557654321
AccountSid=AC...
ApiVersion=2010-04-01
ErrorCode=  (only on failures)
```

Wire this to a queue (Cloudflare Queues, AWS SQS) for processing —
never block in the webhook handler under load.

## INBOUND MESSAGE WEBHOOK

When someone texts your Twilio number, Twilio POSTs to the **Messaging
Webhook URL** configured on the number (or its Messaging Service).

### Standard inbound parameters

| Param | Description |
| ----- | ----------- |
| `MessageSid` | Unique ID of inbound message |
| `SmsSid` | Same as MessageSid (legacy alias) |
| `AccountSid` | Your account |
| `MessagingServiceSid` | If routed through one |
| `From` | Sender (E.164 or `whatsapp:+1...`) |
| `To` | Your Twilio number receiving |
| `Body` | Text content |
| `NumMedia` | Count of media (0 if SMS) |
| `MediaUrl0..N` | Public URL per media item |
| `MediaContentType0..N` | MIME type per media |
| `NumSegments` | How many SMS segments |
| `FromCity`, `FromState`, `FromZip`, `FromCountry` | Geo (when available) |
| `ToCity`, `ToState`, `ToZip`, `ToCountry` | Geo |
| `SmsMessageSid` | Legacy alias |
| `ApiVersion` | API version |

### WhatsApp-specific inbound

- `ProfileName` — sender's WhatsApp display name
- `WaId` — sender's WhatsApp ID (phone without `+`)
- `ButtonText`, `ButtonPayload` — when user taps quick reply
- `OriginalRepliedMessageSid` — when message is a reply

### Inbound Handler (Node + Express)

```javascript
import twilio from 'twilio';
import express from 'express';

const app = express();
app.use(express.urlencoded({ extended: false }));

const validate = twilio.webhook({
  validate: true,
  authToken: process.env.TWILIO_AUTH_TOKEN,
});

app.post('/sms/incoming', validate, async (req, res) => {
  const { From, Body, NumMedia, MessageSid } = req.body;

  // Handle opt-out (Twilio also auto-handles STOP/UNSUBSCRIBE)
  if (/^(stop|unsubscribe|cancel|end|quit)$/i.test(Body.trim())) {
    // Twilio already added them to your opt-out list automatically
    // Optionally update your CRM
    await markOptedOut(From);
  }

  // Download MMS media if present
  if (parseInt(NumMedia) > 0) {
    for (let i = 0; i < parseInt(NumMedia); i++) {
      const url = req.body[`MediaUrl${i}`];
      const type = req.body[`MediaContentType${i}`];
      await fetchAndStoreMedia(url, type, MessageSid);
    }
  }

  // Reply via TwiML (synchronous response)
  const r = new twilio.twiml.MessagingResponse();
  r.message('Got your message — well call you shortly.');

  res.type('text/xml').send(r.toString());
});
```

### Reply Patterns

Two ways to send a reply:

1. **Synchronous TwiML reply** (in webhook response) — simple,
   single message, no delivery tracking on the reply itself
2. **REST API reply** (in webhook handler, before responding) —
   more flexibility, full status tracking, can send multiple messages,
   can use Content Templates

Production pattern: REST API reply, return empty TwiML
(`<Response/>`).

## MESSAGING SERVICES (Sender Pools)

A **Messaging Service** (`MGxxxx`) bundles senders + features into a
managed pool. **Always use a Messaging Service for production sending.**

### Why use one
- **Sender pool:** mix long codes, short codes, alpha senders,
  WhatsApp, RCS, toll-free in one service
- **Sticky Sender:** same recipient always gets messages from same
  number (consistency)
- **Geo-Match:** chooses best local sender for recipient's region
- **Smart Encoding:** GSM-7/UCS-2 auto-replacement
- **Scheduled messages:** required for `sendAt` parameter
- **Link Shortening:** auto-shorten URLs + click tracking
- **Opt-out management:** centralized STOP/UNSUBSCRIBE handling
- **Fallback to Long Code:** automatic when short code fails
- **Inbound routing:** all inbound to any sender in pool routes
  to one webhook
- **MMS Converter:** auto-convert MMS to SMS where MMS unsupported
- **Validity Period:** account-wide message TTL
- **Area Code Geo-Match:** match sender area code to recipient

### Create a Messaging Service via API

```javascript
const ms = await client.messaging.v1.services.create({
  friendlyName: 'RJ Notifications Production',
  inboundRequestUrl: 'https://your-app.com/sms/incoming',
  statusCallback: 'https://your-app.com/sms/status',
  stickySender: true,
  smartEncoding: true,
  fallbackToLongCode: true,
  areaCodeGeomatch: true,
  scanMessageContent: 'inherit',
  mmsConverter: true,
  validityPeriod: 14400, // 4 hours
  useInboundWebhookOnNumber: false, // route all inbound to MS webhook
});

console.log('Messaging Service SID:', ms.sid);
```

### Add senders to the service

```javascript
// Add a phone number
await client.messaging.v1.services(ms.sid)
  .phoneNumbers.create({ phoneNumberSid: 'PNxxxxxxxx' });

// Add a short code
await client.messaging.v1.services(ms.sid)
  .shortCodes.create({ shortCodeSid: 'SCxxxxxxxx' });

// Add an alpha sender (where regionally allowed)
await client.messaging.v1.services(ms.sid)
  .alphaSenders.create({ alphaSender: 'RJBIZ' });
```

### Sticky Sender behavior
Twilio maintains an internal map of `{recipient → assigned sender}`.
Once a sender is paired with a recipient in your service, future
messages to that recipient route through the same sender — even if
you don't specify `From`. Mappings persist long-term.

To **find which sender was used** for a given message, fetch the
message resource — `From` field shows the assigned sender.

## MEDIA RESOURCE (Inbound MMS Storage)

When inbound MMS arrives, media is stored in Twilio's Media Content
Service. The `MediaUrl0...N` fields in the inbound webhook point to
these. You should download and store them in your own infrastructure
within retention window (default 7 days).

### Fetch Media via API

```javascript
const media = await client.messages(messageSid)
  .media(mediaSid)
  .fetch();

// Download bytes via the media URL with HTTP Basic Auth (API Key)
const response = await fetch(`https://api.twilio.com${media.uri.replace('.json', '')}`, {
  headers: {
    Authorization: `Basic ${Buffer.from(
      `${process.env.TWILIO_API_KEY_SID}:${process.env.TWILIO_API_KEY_SECRET}`
    ).toString('base64')}`,
  },
});
const buf = await response.arrayBuffer();
// store buf to S3/R2/etc.
```

### Delete Media (Privacy / Storage)

```javascript
await client.messages(messageSid).media(mediaSid).remove();
```

## OPT-OUT MANAGEMENT (Mandatory Compliance)

US carriers (and many global jurisdictions) MANDATE that recipients
can opt out by texting STOP, UNSUBSCRIBE, CANCEL, END, or QUIT.

### Twilio Auto-Handles
When a recipient texts one of those keywords to a long code or short
code, Twilio:
1. Records the opt-out in your account
2. Auto-replies with a confirmation message
3. Blocks future messages to that number from that sender
4. Does NOT forward the keyword message to your inbound webhook by
   default (configurable per Messaging Service)

### Re-Opt-In Keywords
START, UNSTOP, YES → reverses opt-out

### View Opt-Outs

```javascript
// (Per-service opt-out list)
const optOuts = await client.messaging.v1.services(msSid)
  .messages.list({ /* filter as needed */ });
```

### HELP Keyword
HELP/INFO → Twilio sends configured help message. You should configure
this on every Messaging Service.

## SECURITY HARDENING (Messaging-Specific)

✅ Validate `X-Twilio-Signature` on every inbound webhook (HMAC-SHA1)
✅ Use API Keys + Secret, not Auth Token, for production sends
✅ Use Messaging Services with locked sender pool — prevents fraud
   from rotating numbers
✅ Set `MaxPrice` per send to cap unit cost
✅ Set `ValidityPeriod` to prevent late delivery (e.g., expired OTPs)
✅ Use Messaging Insights / Error logs to catch high-volume failures
✅ Set Usage Triggers (50/80/100% of daily budget alerts)
✅ Audit Sticky Sender mappings periodically — purge stale ones if
   needed via API
✅ Enable Geo Permissions allowlist on the account
✅ For OTPs, use Verify (purpose-built, fraud-protected) over raw SMS
✅ Disclose recording / data use in initial opt-in flow (TCPA / GDPR)
✅ Maintain double-opt-in audit trail (timestamp + IP + form URL)
✅ Encrypt PII before passing to logs/analytics
